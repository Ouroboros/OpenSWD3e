# 第二遍汇编验证方法

## 原则

以汇编为唯一依据，源码视为待查对象，不默认正确。第一遍证据、函数名、注释、测试结果与 swd3-rebuild 的写法都不作为通过依据。

## 每个函数的步骤

1. 只读 reverse/analysis/asm/<地址>.asm（必要时用 IDAT 查询交叉引用与数据），先独立写出行为：
   - 全部分支与出口：找不到、失败、提前返回、返回值驱动的流程、跳转表的每个 case；
   - 位宽与符号：比较是有符号还是无符号、截断与扩展、32 位溢出、除法与移位方向；
   - 调用顺序、参数与返回值的使用，随机数的消费次数与顺序；
   - 读写的全局与结构字段（偏移）、副作用与逻辑时序；
   - 引用的常量表与全局初值（按 exe 字节核对）。
2. 推导完成后再读源码，逐条对照上述清单。
3. 源码中的每个边界保护（越界、空指针、除零）须对照 deviations.md 的登记：只能跳过越界那一次访问，不得改变前进、返回值、随机数消耗或后续流程；没有登记的保护视为差异。
4. 涉及 smooth、宽地图、平台层的分支：确认关闭这些功能时的路径与汇编一致，开启时只改画面或已在 deviations.md 登记。
5. 大函数（跳转表、剧本指令、战斗流程）按 case 分段记录。

## 结论与记录

- 发现差异：先用 `scripts/mark_verified.py <ws> diff <证据> <地址> --pass 2` 标记，修正后重新从步骤 1 完整核对，通过后 `exact --pass 2`。
- 修改影响其他已通过第二遍的函数时，把受影响函数恢复为待复核，在本遍重新核对。
- 证据写入 reverse/evidence/pass2/<模块>.md：每个函数记下汇编推导要点、对照结论、差异与修正。
- CRT 与平台层函数按第一遍的识别方法复核身份，记录于 reverse/evidence/pass2/crt.md。
- 每批函数修正后运行 Linux 构建与单元测试，Windows 构建保持 0 警告；测试结果只作辅助，不代替汇编对照。
- 浮点比较按 x87 标志位理解：`fcomp` 后 `fnstsw ax`，比较结果无序（NaN）时 C0、C2、C3 都置位，所以 `test ah, 40h`（判等）把 NaN 当作相等，`test ah, 1`（判小）把 NaN 当作小于，`test ah, 41h` 把 NaN 当作小于或等于。操作数可能为 NaN 时（如 0/0 的渐变步长），源码要按这个语义写，不能直接用 C++ 的 `==`、`<`。第二遍到 0x00467B50 时已对此前通过的 x87 比较函数逐个复查：0x00414CC0 判步长为零时漏了这一点，已修正并重新核对；寻路、脚本、指令 52、计量器的比较对象来自整数或非负累加，不会出现 NaN。

## 顺序

按 reverse/functions.tsv 的 order 从第一行开始，逐行推进，不跳行。停点写在 GOAL.md 的当前工作。
